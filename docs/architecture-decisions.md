# 🏛️ Architecture decisions

Architecture decisions should explain context, constraints, selected option, alternatives, and consequences. They should be concise enough to review but detailed enough that a future maintainer can understand why a choice was made.

## Current records
- [ADR 0001: Static JSON data source](decision-records/0001-static-json-data-source.md)

## New decision record
Copy [the decision record template](templates/decision-record.md). Use a unique sequential identifier. Update [decision log](decision-log.md) and link the record from affected technical documentation.

Do not create an ADR for every small CSS adjustment. Record decisions that constrain future architecture, security, data, deployment, or maintenance.
