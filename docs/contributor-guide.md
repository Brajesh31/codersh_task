# 🤝 Contributor guide

Start with [CONTRIBUTING.md](../CONTRIBUTING.md), then review [local development](local-development.md), [code standards](code-standards.md), and [testing](testing.md).

## Where to contribute
Good bounded areas include search/filter behavior, resilient data display, accessibility improvements, documentation accuracy, test coverage, and CSS responsiveness.

## Before proposing infrastructure
A backend, database, identity provider, analytics SDK, or deployment platform changes the project's trust boundaries. Open a design issue that describes user need, data processing, threat model, operational ownership, and maintenance costs.

## Contribution safety
Use synthetic records and safe fixture data. Never include real employee personal details or secrets in a patch, issue, screenshot, or log. Verify every documentation link and do not claim a test passed unless it was run.
