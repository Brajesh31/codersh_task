# 📖 Glossary

| Term | Meaning in this repository |
| --- | --- |
| Employee record | One object in the public JSON array |
| Employee ID | Required unique identifier used as the React list key |
| Department | String used for exact matching in the department selector |
| Static asset | File served directly from the Vite public directory |
| Normalization | Filtering malformed rows and supplying safe optional defaults |
| Directory card | Semantic button summarizing one employee |
| Profile dialog | Modal detail view for a selected employee |
| localStorage | Browser-local key/value store used for filter preferences |
| Vite base path | URL prefix configured by Vite for build assets |
| SPA fallback | Hosting behavior that serves `index.html` for client-side routes |
| Synthetic data | Invented sample data that does not identify real people |
| Public data boundary | The fact that any visitor can request a published static asset |
| CI | Automated checks triggered by repository events |
| ADR | Architecture Decision Record explaining a technical choice |

Use these terms consistently in issues and documentation. The words "API", "database", "authentication", and "admin" must not be used to imply those capabilities currently exist.
